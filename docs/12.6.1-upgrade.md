# Docxodus 12.6.1 integration

The browser engine and optional `@docxodus/export` companion are pinned to
12.6.1. Reinstall dependencies and copy the matching runtime with
`npx rdv-copy-runtime public/docxodus` (or `npm run sync:wasm` in this repository).
The checked-in runtime files are the unmodified, digest-verified npm assets.

## Interior formatted typing

[Docxodus 12.6.1](https://github.com/JSv4/Docxodus/releases/tag/v12.6.1) resolves
[upstream #799](https://github.com/JSv4/Docxodus/issues/799). Its supported
`session.replaceMatch(match, text, format)` operation can insert at an ordinary
character boundary inside a plain text run, applying the format only to inserted
text. This avoids the full-package checkpoint and receipt used by the previous
text-plus-format batch while preserving rollback and one-step undo/redo.

The canvas now attempts that operation for a contiguous styled draft, retaining
the original selection so identical spaces and repeated text cannot shift the
formatted span. The native engine decides whether the underlying Word structure
supports the insertion. Fields, inline containers such as hyperlinks,
mixed-content runs, and positions inside UTF-16 surrogate pairs remain excluded
from the new interior insertion path.

If the engine refuses a pure insertion with `offset_out_of_range` and its version
has not changed, the editor uses the existing public surgical text-plus-format
batch. It does not retry an unrelated failure or a changed version. Disjoint
drafts and compound structural edits also retain atomic batches. No native
runtime or private editing API is patched.

This limitation occurs in the NVCA fixture's footnotes: a run with a leading
`w:tab` still requires the batch and measured an 816 ms input response.
[Upstream #802](https://github.com/JSv4/Docxodus/issues/802) requests a supported
atomic operation for that case. The ordinary interior insertion improvement
does not establish an editor-wide 150 ms maximum.

## Rendering and API compatibility

The live session, changed-block renderer, conservative metadata caches, and
cooperative pagination remain in use. All published upstream entry points remain
exposed by the library.

The published pagination source is byte-identical to 12.6.0 (SHA-256
`2b67cf77f5383db0871647e8c40ca367e1c79cfb3f996120edbf6d7c707e31c0`), and the
native page-map contract is unchanged. The generated cooperative adapter retains
that source digest; native differential tests check its output.

See [performance measurements](performance.md) for validation, reproducible
workloads, and the limits of the observed latency results. The previous
[12.6.0 integration notes](12.6.0-upgrade.md) remain as historical context.
