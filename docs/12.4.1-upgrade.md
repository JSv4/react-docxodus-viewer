# Docxodus 12.4.1 integration

The objective is complete React access to the Docxodus 12.4.1 engine APIs, with
React-owned UI. The upstream browser editor and ribbon are not required.

## Completion requirements

- [x] Pin the engine and matching WASM assets to 12.4.1; define correct peer and
  subpath boundaries, including an optional Node export companion entry.
- [x] Preserve existing viewer controls, styling, controlled inputs, worker
  conversion, loading placeholders, zoom/fit, and revision expansion behavior.
- [x] Migrate native revision listing, including structural families, grouped
  moves, diagnostics, selective/bulk resolution, and comparison formatting details.
- [x] Expose all conversion options, paragraph fragmentation, canonical anchors,
  measured PageMaps, citation registration, navigation, and invalidation.
- [x] Provide React runtime and session lifecycles with complete typed session
  access: projection/search, text/formatting, structures/tables, lists/styles,
  headers/footers/page setup/fields, notes, images, links, bookmarks, content
  controls, annotations/comments, tracked changes, undo/redo, batches,
  preconditions, previews, semantic changes, and verification.
- [x] Provide comparison hooks/UI for redlines, native comparison revisions,
  edit scripts, semantic changes, combined products, fan-out batches, N-way
  consolidation/conflicts, and accept/reject projections.
- [x] Provide native comment/annotation hooks/UI and preserve external annotation
  projection, validation, search and OpenContracts exports.
- [x] Provide package manifests, deliverable verification, delivery receipt
  verification, and redline reversibility proof through React APIs and review UI.
- [x] Provide standalone paginated HTML with all review/comment/font/resource
  options and reports; expose the matching Node/PDF companion without adding
  Node dependencies to browser consumers.
- [x] Provide React history controls and hooks covering host-owned storage,
  IndexedDB, metadata/version pagination, preview/download/compare, checkpoints,
  restore/retry, time lookup, changes/operations/proposals, and portable archives.
- [x] Update the demo and public documentation with usable examples for every
  capability family and an explicit migration guide.
- [x] Verify type checking, lint, unit/integration behavior, built package
  boundaries, and actual 12.4.1 WASM browser workflows. Check API coverage against
  the published declarations, not just against the functions this project uses.

## Evidence and decisions

- Baseline package: viewer 0.6.0, Docxodus 6.2.0. All 50 original vendored WASM
  files match that package.
- PR base: viewer 0.7.0, Docxodus 7.0.1. The final package is 0.8.0 and retains
  current main's dependency and CI updates.
- The 12.4.1 npm tarball and upstream API declarations were inspected directly.
- Before migration, the source type checks with 6.2.0 and reports 14 diagnostics
  with 12.4.1. `RevisionListEntry` is the native-document listing;
  `DocxDiffRevision` is the separate two-document comparison record.
- Existing uncommitted revision-panel styling and filter/expansion fixes are user
  work and must be retained.
- The upstream worker session has a narrower API than the main-thread session.
  Complete programmatic editing therefore requires the full core session API;
  worker conversion and the upstream worker API remain available separately.

## Validation results

- `npm run check`: lint, 44 unit tests, TypeScript, library/demo builds, and API audit pass.
- `npm run test:browser`: all 12 actual-WASM integration scenarios pass.
- Pagination additionally passes navigation at 200% zoom, paragraph fragmentation,
  exact PageMap registration, renderer mismatch rejection and mutation invalidation.
- Production preview passes three workflows: edit/comment/checkpoint/restore/HTML
  export; sample editing, navigation and checkpoint previews; and mobile use with
  dark OS preferences.
- The generated sample passes native deliverable verification with zero findings
  both before opening and after a session save.
- `npm run test:package`: the packed artifact imports in an isolated consumer,
  consumer declarations compile, and its asset-copy helper works.
- `npm run test:pdf`: Node companion API identity passes. Native PDF rendering is
  skipped because this host denies the user namespaces Chromium's sandbox requires.
  `DOCXODUS_REQUIRE_PDF=1` makes that limitation fail the test on a required render host.
- All 80 vendored framework files match the installed 12.4.1 package byte for byte;
  the exporter asset graph is digest-verified before staging.
- The declaration audit covers all 363 core, six worker, 57 browser-export and
  48 Node-companion exports. The 118 core runtime exports preserve identity.
- `git diff --check` passes. Verified upstream runtime assets are marked vendored
  and exempt from newline/whitespace transformations to retain their identity.

## Integration decisions

- The package is ESM-only because Docxodus 12.4.1 provides ESM import conditions.
- The React paginator uses the core `PaginationEngine`; no upstream editor/ribbon
  or `docxodus/react` module is loaded by the browser library or demo.
- Each viewer isolates document CSS in a ShadowRoot and retains root styling,
  block selection, footnote links, citations and page navigation.
- The document studio uses a warm canvas, compact inspector, paragraph quick
  actions, native text/heading navigation, keyboard commands and focus mode. A
  reproducible sample contains actual tracked changes and a comment. Advanced
  operations remain accessible in the panels.
- Selection highlights do not change document formatting. Editing reads complete
  paragraph text and refreshes after apply/undo/redo; hidden viewers wait for a
  measurable layout before pagination.
- Native session saves retain PowerTools anchor metadata. Minimal hand-authored
  packages without the matching markup-compatibility declaration can produce
  undeclared-attribute findings. The sample declares the ignorable extension;
  verification reports remain available for arbitrary user documents.
- Standalone HTML export loads a byte-identical static bundle. Vite development
  serves those assets before transforms; production copies them unchanged.
- Full session methods keep native synchronous results and callbacks. Main-thread
  sessions provide editing; worker conversion remains available and cancels owned
  initialization when unmounted.
- History keeps pending publications intact, waits for leased native operations
  before closing handles, and preserves acknowledged checkpoints if a later list
  refresh fails.

The implementation and documented API coverage are complete. PDF execution on an
eligible sandboxed render host remains an environment-specific validation step.
