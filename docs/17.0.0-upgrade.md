# Docxodus 17.0.0 integration

The browser engine and optional `@docxodus/export` companion are pinned to
17.0.0, up from 12.6.2. Reinstall dependencies and copy the matching runtime with
`npx rdv-copy-runtime public/docxodus` (or `npm run sync:wasm` in this repository).
Runtime files are copied from npm and digest-verified without modification.
No public engine method was removed. Five major releases change behavior; the
parts that reach this library's users are below. The upstream
[release notes](https://github.com/JSv4/Docxodus/releases) have the complete list.

## Breaking changes for applications

### Text offsets count tabs, breaks, hyphens and symbols

Since 15.0.0 every native offset counts one character for each visible run atom.
There is no setting for the earlier counting.

| Word content | Character | Before |
| --- | --- | --- |
| Tab, positional tab | `\t` | none |
| Line, page and column break | `\n` | none |
| Nonbreaking hyphen, soft hyphen | U+2011, U+00AD | none |
| `w:sym` symbol | the stored character, often private-use | none |

This affects `onTextSelectionChange` (`span`, `text` and `blockText`),
`editor.select(anchorId, span)`, `getFormatting` spans, search results, comment and
annotation spans, and anchor previews. **Recompute offsets stored by an earlier
version** from the new visible text. Annotations saved in a DOCX use bookmarks and
do not move.

Read-only selections previously used a separate approximation that included note
reference numbers, deleted text and direction marks. They now report the same native
offsets as the editor.

### Other changed results

- **Pages.** Line heights, kerning, spacing, footnotes and tables follow Word more
  closely, so page counts and breaks change. Discard stored PageMaps, citations and
  rendering baselines, and change your `rendererFingerprint`. The NVCA fixture goes
  from 65 to 49 pages in the `DocumentEditor` block, partly because of the
  [style isolation](#document-style-isolation) fix below.
- **Markdown patches.** `EditResult.patch.markdown` contains only changed blocks.
  Apply `blocks` and `removedAnchorIds`, honor `fullDocument`, and call `project()`
  for a whole document. Undo and redo return no patch. Editor-owned sessions default
  to `emitMarkdownPatch: false` and are unaffected.
- **Comparison.** The default author is `Docxodus`, formerly `Open-Xml-PowerTools`;
  pass `authorForRevisions` to choose one. Redlines, move detection, edit scripts and
  semantic changes are more granular, so rebuild caches of them. Consolidation accepts
  existing revisions first; `preserveInputRevisions: true` still retains them.
- **Review details.** Paragraph-mark formatting is reported with `mark`-prefixed
  properties such as `markFontSize`. `RevisionPanel` names them "Paragraph Mark …".
  Comment dates prefer the modern UTC timestamp.
- **Content controls.** A date control filled without `displayText` shows the date in
  its own format, such as "15 December 2026", instead of ISO text.
- **Symbol fonts.** Wingdings and similar text displays its Unicode equivalent. The
  stored character stays in `data-docx-symbol-text`; use that attribute, not
  `textContent`, to line HTML up with document text.
- **Input limits.** Parts nested past 128 elements (stories) or 256 (others) fail with
  `xml_depth_limit_exceeded`.

## Editing on the page

Tabs, breaks, special hyphens and symbols are single caret steps. Backspace and
Delete remove one as one character, and undo restores its original XML, including a
page break's type or a positional tab's alignment. Where equal characters can be
different content (a page break beside a line break), an edit uses the actual
selection rather than a text diff, and inserting beside such a character never
rewrites it. Paragraphs containing page breaks, column breaks or symbols were
previously read-only on the canvas; most are now editable.

Pagination consumes the marker between the parts of a paragraph split by a page or
column break. `splitParagraphs.ts` records the break before flow, without adding
layout content, and restores it as a zero-size element afterwards.

The engine now draws a note's number inside its first paragraph. It is excluded from
text and kept when that paragraph is re-rendered on its own.

**Joining paragraphs while tracking changes is still refused**, without recording
any part of it. The engine can now record the join, but with revisions hidden both
paragraphs render as one block that belongs to neither, which the canvas cannot map.
`session.mergeParagraphs()` is available to applications directly.

## Rendering integration

`PaginationEngine` now writes measured line heights into paragraphs before laying out
pages, and measures unscaled. A block re-rendered after an edit is prepared the same
way in an unscaled shell of its section, so unchanged geometry still keeps its pages
at any zoom. A draft's new lines use natural line height until it commits.

The cooperative adapter copies a closure of five upstream modules: `pagination.js`,
`line-metrics.js`, `word-text.js`, `markup-balloons.js` and `exact-row-text.js`. The
generator pins the SHA-256 of each, requires every adapted method to exist, refuses
module-level side effects, and fails on any name the generated file cannot resolve.
Native and cooperative pagination produce identical pages and PageMaps on the
synthetic and NVCA documents. The portable PageMap contract is byte-identical to
12.6.2, so its cache needed no change.

Live block updates fall back to the complete converter for the new
`showFormattingChanges`, `showInsertionsAndDeletions` and `revisionPresentation`
options when the document has revisions, because the block bridge cannot express them.

### Document style isolation

A document now lays out as it would on a page of its own. Text styles that the host
element inherits, such as font, line height, spacing, text transform and direction, no
longer reach document content; CSS custom properties still do. Before, the
`DocumentEditor` block's interface style (`12px/1.5`) laid out every paragraph without
its own spacing at 1.5 lines, so NVCA showed 59 pages there against 49 in the studio
and in the engine alone (LibreOffice: 48). 12.6.2 showed the same gap, 65 against 52.
A browser test now requires the viewer's PageMap to match the engine's in a separate
document under a host with conflicting styles.

Use `conversionOptions.additionalCss` to style document content. A host that relied on
inherited fonts or colors reaching documents must move them there.

### Workarounds reviewed

- **List labels: removed.** 12.6.2 returned stale counters after a split or merge, so
  each Enter in a document with numbered lists saved and reopened the package. Live labels match
  a reopened session on 17.0.0 in randomized tests (about 23,700 comparisons, 14 kinds of
  edit, synthetic and NVCA documents); the same test fails on 12.6.2.
- **Measuring at scale 1: kept.** Pages measured while zoomed still overflow.
- **Anchor kind reconciliation: kept.** The mismatch did not reproduce on the NVCA
  document with either version, which does not prove it is gone.

## New capabilities

Every export and session method is available through the existing entry points and
hooks; the API audit covers 390 core, 9 worker, 67 browser-export and 50 Node exports.

| Area | Added |
| --- | --- |
| Tables | `setTableProperties`, `setCellProperties`, `getTableProperties`, `setTableStyle` |
| Lists | `getListLevels`, `setListLevels`, `continueNumbering`, `setListMembership` |
| Paragraphs | Absolute indents, keep with next/lines, widow control, contextual spacing |
| Review | `setRevisionIdentities`, `getRevisionAuthorNameStatus`, `listRevisions(filter)` |
| Inspection | `listNotes`, `getAnchorLocations`, `maxResults` searches |
| Insertion | `replaceMatch(…, deletedTextSide)` chooses a side of tracked deleted text |
| Comparison | `minimumAnchorWordCount`, `trackNumberingChanges`, `trackCellInsertionsAndDeletions` |
| Display | `revisionPresentation` (Word style), `showFormattingChanges`, `showInsertionsAndDeletions`, `semanticLists` |
| Export | `markupPresentation`, `markupVisibility`, comment balloons, `additionalCss`, embedded and local fonts |
| Worker | `requestTimeoutMs`, `withRequestOptions`, more error codes |

`setRevisionIdentities` notifies React like the other review settings, and the new
queries keep local edits eligible for block rendering.

## Validation

Lint, types, library and demo builds, the API identity audit and the generated
adapter check pass, with **143 unit tests and 88 browser contracts** (two opt-in
skips). The packed-consumer checks and eight production preview tests pass.

The NVCA integrity test passes with every assertion unchanged; one paragraph lookup
now includes its tab. It covers 234 body and 110 footnote paragraphs, all
editable, with 13 modified and one added paragraph, 31 commits, and independent XML
inspection of the saved package. The performance guards pass. See [performance](performance.md) for
input latency.

A sweep of 190 documents from the upstream test corpus opened each in the editor with
12.6.2 and 17.0.0. All 190 paginate without errors on 17.0.0; three failed on 12.6.2.
In the 187 that open in both, 18 paragraphs are read-only with either version. Two
bookmark and cross-reference paragraphs became editable, and two charts became
read-only: they now show a placeholder where an empty editable paragraph hid them.

PDF rendering was not exercised: this host denies the unprivileged user namespaces
required by Chromium's sandbox, as in earlier upgrades. Run
`DOCXODUS_REQUIRE_PDF=1 npm run test:pdf` on an eligible host.

## Known issues

- **`#x200e` in split paragraphs (upstream, new;
  [Docxodus #1862](https://github.com/JSv4/Docxodus/issues/1862)).** In a paragraph holding both a page
  break and a line break, such as
  `<w:t>AB</w:t><w:br w:type="page"/><w:br/><w:t>CD</w:t>`, the paginated converter
  writes the direction mark after the line break as the text `#x200e`. The viewer
  corrects exactly that shape before layout. Standalone HTML and PDF export use the
  verified upstream bundle and still contain the text.
